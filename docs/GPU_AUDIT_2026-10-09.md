# GPU / 显存审计：保留视觉与交互

## 结论与保留项

本轮**没有测出超过波动的显存下降**，也没有复现“此网站独占接近 3GB”的结论。用户看到的是 Edge 的 GPU 进程指标，不是单个页面指标；原始窗口、其他标签页、浏览器缓存与屏幕条件尚未完全复现。

唯一保留的产品修改在 `static/js/pages/home/scene-parallax.js`：采集视差元素时排除固定背景容器，再单独添加它。背景在首次初始化后带有 `data-home-parallax`，旧实现恢复首页时会将它加入两次。三次初始化后，每帧背景 x/y 写入次数从 `[2,4,4]` 变为 `[2,2,2]`。原深度、缓动系数、3D 变换、合成层提示、移动端策略和离场清理均保留。

没有改 CSS、图片、频谱精度、帧率上限或背景动画；朋友页的统一世界投影及防闪动结构不动。保留项有独立的去重/维护依据，不把它包装成已经验证的 GPU 降幅。

## 测量条件

- 基线为 `8106945` 对应的本地构建；修改后重新用同一已有镜像离线构建，178 页 / 231 个静态文件。未发布、提交或推送。
- NVIDIA GeForce RTX 5070 Laptop GPU，驱动 595.99.02；Edge 154.0.4258.53，确认 ANGLE / NVIDIA 硬件合成启用，不使用软件渲染作 GPU 证据。
- 每次启动独立 Edge 进程，以 CDP 取得 GPU PID，再从 `nvidia-smi -q -x` 读取该进程显存；不把整张显卡或其他应用占用归于网站。
- 每轮新上下文与相同构建/离线资源，等待页面就绪后预热 8 秒，随后每秒取一次显存，共 5 次。每个版本 3 轮，先求每轮中位数，再求轮间中位数；记录全部样本范围。最终前后交替运行，GPU 性能试验不并发。
- 最终测量是正常显示窗口：实际 CSS 视口 2560×1440，实际 DPR ≈2（检查浮点误差），相同视觉视口 2545.03、scale=1。持续分发相同正弦路径的鼠标 PointerEvent，触发原视差逻辑。帧间隔是 RAF 观察值，**不是点击延迟，也不是人工拖动评价**。
- 全部本地背景使用真实图片；外部图片、API 用固定离线响应，因此线上第三方加载、登录后的内容和实际全部标签页占用未测量。首访完整开场的峰值、长时间游览峰值、GPU 利用率/功耗未测量。
- Headless 与正常窗口的渲染表面及基线不相同，不能混合比较。CDP 图层尺寸在两种模式中存在单位差异；原始探索日志中的图层字节估算不作为显存证据，保留的测量脚本只记录图层边界和合成原因。

这是小样本保护检查，不支持对用户原始 3GB 场景外推百分比。修复只影响恢复/重复初始化路径，最终 GPU 检查的直开首页路径本来就不会重复；其显存变化按噪声处理。

按 optimize 逐项评估保留项：主要指标 **0**，资源 **0**，稳定性 **0**，结构 **+1**。没有把少一次处理或测试通过计为故障率降低，也没有重复对同一显存证据加分。

## 给 optimize skill 的可复用建议

1. **避免同一证据重复计分**：当显存本身就是主要目标时，不应又在资源维度对同一数字加分；说明资源主目标该计在哪一列。
2. **资源归因与代理指标**：GPU 共享进程、整卡占用、独立测试进程、图层数量/面积是不同口径。要求声明口径，不能把估算的纹理面积当实际显存，也不能将独立进程节省直接外推至用户全部标签页。
3. **实际条件与代表性负载**：验证实际视口、DPR、渲染器和采样时长，区分正常窗口/无头、静止/操作、启动峰值/稳态；使用交替顺序，避免缓存与系统漂移制造假收益。DPR 检查允许合理浮点误差。
