# 页面加载与流畅性

## 统一加载规则

`web/static/resource-readiness.js` 是首页启动、公开页切换以及展示页/后台跨文档过渡共用的资源就绪入口。

- 首先等待页面模块初始化、样式和场景布局，再识别实际首屏图片。星图节点在初始化时同步定位；回忆轨道只保留 JS 平滑，不再叠加 CSS 位移延迟。
- 可见图片要完成下载和解码才进入就绪状态，包括没有预写尺寸的 Markdown 图片。修改同一个图片元素的 `src` 会开始新的等待，不能复用上一张图片的完成状态。
- 页面背景、伪元素背景以及 `data-bg` 场景参与等待。远处图片按接近视口的位置加载，不要求整条时间轴全部下载后才能操作。
- 第二轮将图片阻塞预算从 8 秒降为 1.2 秒，防止一个慢头像锁死整页。超时图片保留占位，解码后显示；失败图片不显示破图。图片自身请求观察在 30 秒时结束等待，但后续响应成功仍能恢复显示。
- 页面 CSS 最多等待 8 秒，模块初始化最多等待 12 秒；失败时退回完整文档导航，而不是悄悄显示未初始化的页面。
- 保留入场方向和视觉，缩短动画；取消 2.22 秒的切页固定停顿及额外等待加载动画整圈。缓存命中时无需闪现加载转圈；减少动画模式下不保留人为的动画等待。

## 带宽和重复工作

- 首页仅当前推荐封面优先加载，切换时先准备下一张封面；音乐不再使用 `preload=auto` 抢占图片带宽。
- 删除旧 `lazy-backgrounds.js` 和旧版未启用的页面导航实现，去掉分散的首页/切页图片预加载代码，统一维护一份资源调度器。
- 图片就绪 Promise 按元素和源去重，背景预热缓存最多保留 96 项；换页重新绑定观察器，释放旧观察目标。
- 修复空闲任务取消时使用错误句柄的问题，移除切页后重复调度模块的延迟扫描。
- 第二轮将同一容器同时进行的模块扫描合并为一个 Promise，首次加载不再通过 `pageshow` 重复初始化；图片布局读取集中在属性更新之前。加载预算由 `SonglineResources.policy` 统一维护，状态报告包含尚未完成的资源数，不把提前解除阻塞误报成全部加载成功。
- `/uploads/` 保留原有媒体解析和权限边界，增加 `Cache-Control: public, no-cache`。这里的 `no-cache` 是允许存储但使用前验证，不是 `no-store`；未改变的文件通过 `Last-Modified` 验证返回 304，不重复发送图片字节。可变路径不采用永久 immutable 缓存。
- 不改原图、运行数据及素材目录，不生成兼容副本，不自动提交 Git。

## 验证

2026-09-14 在本地 Docker 预览与无头 Edge 中验证：

- `go test ./...`：通过，包含运行时媒体优先级及条件请求 304 测试。
- `node --test tests/document-transition.test.cjs`：3 项通过，保持后台内部无黑幕、展示页与后台之间有过渡。
- `tests/resource-readiness.browser.cjs`：慢图片、失败请求、安全超时、替换图片源、无尺寸图片和延迟背景通过。
- 1440×900：首页 → 朋友 → 回忆 → 工具 → 档案 → 首页，逐页检查可见图片均参与就绪管理；第二轮人为延迟头像 5 秒，验证页面先解除阻塞，头像保留占位直到解码完成。热缓存切页测试约 1 秒，不再保留旧的 2.22 秒固定等待。
- 390×844、减少动画模式：直开回忆，切换工具、档案、首页通过。
- 截图写入被 Git 忽略的 `local-only/performance/`，用于本地检查。

浏览器测试需要 Playwright 和 Edge；设置 `BLOG_TEST_URL=http://127.0.0.1:8080` 时会额外验证真实站点。当前真实站点慢头像用例使用本站种子素材 `/uploads/admin/friends/kfc.jpg`。

以上是本地功能与加载策略验证，不等同于生产环境 Core Web Vitals 达标证明。大尺寸原图、第三方头像服务器速度和用户网络仍会影响等待时长。部署后应在实际网络下测量 LCP、INP、CLS；后续压缩/多尺寸派生资源应保留原图，不能以批量降低素材质量替代加载逻辑修复。
