# 背景就绪与页面展示顺序（2026-10-05）

目标：保留现有背景、布局和过渡效果，修复“加载结束后先出现纯色底，随后背景才出现”的展示问题。本轮没有压缩、替换或重写原图，也没有部署或修改运行数据。

## 原因与修正

原来的所有图片共用 1.2 秒等待预算，主背景也会被当成慢头像提前放行。普通直开/再次访问页面没有首屏揭示保护，主题幕布则按固定定时器退去，不等待目标背景。背景通常为 1–2.5 MB，等模块完成后才预热也偏晚。

现在区分主场景与次要媒体：

- HTML head 在阻塞脚本、样式之前，只 preload 当前主题的实际场景图片，并设置高优先级。站内切页在解析目标 HTML 后、同步样式和初始化模块前就开始预热；主题按钮按下后也提前预热目标主题。
- 运行时仍以实际 CSS 为准检查主背景，包括 body、全站背景层及其伪元素；提示清单不替代就绪检查。工具页已隐藏的全站背景层不再误下载。
- 主背景等待下载及解码，随后给浏览器绘制帧，再退出首屏覆盖、首页启动动画、切页幕布或主题幕布。直开、再次访问和减少动画模式均遵循这一检查。
- 主场景预算独立为 8 秒；头像、封面等次要媒体保持 1.2 秒预算，两类等待并行。缓存命中不增加固定停顿，原有动画的最低时长保留。
- 极慢背景不会永久锁页：预算耗尽后内容可用，明确显示“背景仍在加载”；失败时提供重试。迟到响应解码成功后提示自动消失，包括晚于 30 秒图片观察期限的响应。无脚本初始化时的首屏覆盖有 18 秒兜底。
- 增加 `sceneReady`、`scenePending`、`sceneFailed` 等报告字段；`data-scene-state` 区分 loading、pending、error、ready。超时不冒充全部资源就绪；`lastReport` 是一次 prepare 的快照，迟到恢复的当前状态看 `data-scene-state`。
- 共享预热不随一次切页取消；缓存及解码成功 URL 集合最多保留 96 项，不长期保留原始 Image/解码位图。旧场景的迟到响应不能覆盖新场景状态。

另修复了朋友页的固定夜景污染目标页面的问题：现在先确定目标主题再应用目标样式。从朋友页返回浅色主页，不再额外请求 1,981,926 字节的夜景图。错误主题图片与被隐藏的全站背景都属于无用带宽，而不是简单延长加载动画。

公开页面的共享脚本 URL 跟随站点资源版本；后台共享资源版本也已更新，避免继续命中旧调度器。主题与跨文档、首屏覆盖各自保留边界，首屏转圈不会把跨文档幕布变成一个小圆圈。

## 验证

全部浏览器请求由本地测试响应；背景使用仓库中的真实 PNG，其他图片和 API 使用替身，不产生线上阅读计数。

- 优化前复现：普通进入与首次首页启动在背景未响应、未解码时已退出加载；从朋友返回主页额外请求夜景图。
- 32 组冷场景：390/1440 宽度 × 深浅色偏好 × 首页、档案、阅读、公告、工具大厅、工具内页、朋友、回忆。代表页阻塞背景超过原来的 1.2 秒，揭示仍保持覆盖。响应后额外延迟 decode 100ms，验证不是只等下载结束。预加载和实际请求只包含当前场景图片。
- 16 组前后对比：两种宽度、两种主题：首页、档案、工具、朋友的检查容器几何一致。首页截图保留原背景和布局。
- 首次首页启动在两种宽度下等待背景；跨文档到达在普通/减少动画模式下等待背景，并检查幕布保持全屏尺寸。
- 两种宽度分别完成两轮站内往返和延迟主题切换；热切页小于测试上限 2.2 秒，不加入 8 秒固定等待。目标主题背景未响应时幕布不按旧固定定时器退出。
- 合成用例覆盖短预算超时、迟到恢复、旧响应隔离、切页复用预热、失败重试及晚于观察期限的恢复。
- 原有 `resource-readiness.browser.cjs` 图片测试、隐私抽屉浏览器测试、Node 单元测试、离线 Hugo 构建、Go test/vet 通过。
- 连续切页三轮：预热后的后两轮保持稳定，手机为 2149 个节点/218 个监听，桌面为 2179 个节点/218 个监听，文档数均为 14，没有逐轮累积。

这些检查证明加载契约与展示顺序，不代表公网 LCP/INP 达标或真机 GPU 上传耗时的保证；原始背景字节未减少，实际弱网仍需要等待其传输。

## 复现

隔离构建与截图/报告位于 Git 忽略的 `local-only/scene-readiness/`。设置可用 Playwright 的 Node 依赖路径后执行：

```sh
BLOG_UI_BASELINE=/absolute/path/before/public \
BLOG_UI_BASELINE_REF=a8c299c027f0bb5b279f8e0628f6ca2a734aab9f \
BLOG_UI_BUILD=/absolute/path/after/public \
node tests/scene-readiness.browser.cjs
```

基线共享 web 脚本从指定 Git ref 读取，默认 HEAD；前后 Hugo 输出应来自对应版本和同一份内容。可设置 `BLOG_SCENE_PHASE=entry`、`cold`、`comparison`、`dynamic` 或 `synthetic` 定向验证；默认完整检查，各阶段报告分开保存。省略基线时只验证当前实现。
