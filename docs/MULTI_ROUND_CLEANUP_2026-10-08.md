# 多轮清理 · 2026-10-08

目标：保持现有外观与功能，分三轮减少无效加载、重复初始化和重复 DOM/样式写入。对照基线是上一轮冗余清理后的构建，不把此前删除的旧朋友数据及重复 Markdown 渲染器再次计入本轮收益。

## 第一轮：缩窄音乐舞台的样式依赖

- 独立音乐工具不再请求玻璃游戏布局、工具通用布局及工具搜索覆盖样式。模板直开与 AJAX 补载规则同步调整。
- 提取仍在使用的图标状态和帮助弹窗至 `static/css/tools/tool-dialog.css`；其他工具按原相对层叠顺序加载，音乐舞台只引入这部分共享能力。
- 移除公共玻璃布局中的旧音乐补丁；封面隐藏、全屏等由音乐自己的样式负责。补齐原来继承的操作栏对齐和间距，不改变最终外观。
- 第一轮音乐初始页面实际请求的本地 JS/CSS 文件合计减少 42,993 字节；包含后两轮调度保护后，最终仍减少 40,974 字节（约 40 KiB）。这是未 gzip/Brotli 压缩的文件字节差，不是测速结果。

## 第二轮：取消多余扫描与依赖初始化

- 同一次选择阶段的相同 selector 只查询一次，阶段结束立即释放缓存，新注入内容/新页面重新判断。
- 用 key 索引依赖，同次扫描的共享依赖只执行一次初始化，保留新页面重入能力。
- 统一取消 runtime idle、原生 idle、RAF 和 timer；离场/立即 ready 清除排队任务，代次校验阻止迟到回调。不同根区域合并扫描，断开的 DOM 不再触发初始化。
- 没有导出预期 API 的加载失败脚本移除标签，避免重试留下无用节点。
- 增加 9 项专项单元测试，覆盖 30 次扫描突发、四种调度路径、离场、迟到任务、动态注入、依赖去重与音乐样式边界。

## 第三轮：首页播放器复用与按变化更新

- 歌单按音乐来源构建一次；切歌保留行节点和键盘焦点，只改变当前行状态。异步元数据只更新当前行文字。
- 去掉逐歌曲的点击闭包，改为一条列表委托监听；新来源与离场释放旧节点/引用。
- 频段边界与固定权重预计算；柱高保留原公式和精度，只有值变化才写 CSS。没有人为降低正常频谱的帧率。
- 页面隐藏停止视觉帧链但不停止音乐，回到页面恢复单条帧链；离开页面释放音频上下文和文件 URL。
- 增加 3 项专项单元测试及真实浏览器对照。单元测试包括 300 行歌单、变化的频谱、后台恢复和销毁。
