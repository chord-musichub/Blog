# 服务端架构

`cmd/server` 保持单一 Go package，以便现有部署方式、路由和数据格式完全兼容；代码按职责拆分，避免继续把启动、配置与业务处理堆进入口文件。

| 文件 | 职责 |
| --- | --- |
| `main.go` | 服务启动，以及尚未迁出的业务处理函数。 |
| `types.go` | 领域模型、状态常量、共享运行参数。 |
| `config.go` | `.env` 加载、环境变量校验、后台路径和公开 API 的 CORS 规则。 |
| `application.go` | 应用实例创建与后台模板函数。 |
| `routes.go` | HTTP 服务配置、路由注册与兼容的积分 API 路径别名。 |
| `config_test.go` | 路径、来源校验、运行参数和 API 别名的回归测试。 |

## 配置边界

真实配置只保存在本地 `.env` 或服务器环境变量中；源码仅提交 `.env.example`。进程环境变量优先于 `.env`，便于 Docker 和 systemd 覆盖。

除管理员凭据与公开 URL 外，还可以使用以下可选参数：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `HUGO_BUILD_TIMEOUT_SECONDS` | `180` | 单次 Hugo 构建的最大耗时。 |
| `MAX_UPLOAD_BYTES` | `104857600` | 单个后台上传请求的最大字节数。 |

## 后续维护规则

- 新环境变量放入 `config.go` 与 `.env.example`，不要在处理函数中读取环境变量。
- 新公开接口在 `routes.go` 注册；若需要保留历史 URL，使用 `registerScoreRoutes` 这类集中登记方式。
- 触发公开站重建必须调用 `runHugo`，它已串行化，避免并发请求同时写入 `published/`。
- 新页面样式优先放在独立、带标题的 CSS 区块；未经视觉回归，不重排既有级联顺序。
