# 性能优化与回归记录

目标：保留现有内容、视觉风格和交互；以可重复测量找到实际瓶颈。测试不部署网站、不覆盖原图、不写真实阅读计数或用户内容。

## 已落地的优化

- 本地 JPEG / 普通 PNG 的小图展示使用 `/uploads/…?preview=640`；工具图标使用 `preview=160`。回忆放大查看、媒体编辑和源文件引用仍指向原图；外部图片、已有查询参数、WebP/GIF/SVG、特殊色彩 PNG 等保持原样。
- 预览在服务端按需生成并原子缓存，不改原文件。缓存最多 256 MiB / 512 个文件；先确认原图存在再读取缓存，避免删除后仍暴露旧预览。名称、文件大小、修改时间、尺寸及算法版本参与缓存标识。支持 ETag、条件请求、HEAD 和 Range。
- 单次只运行一个图像解码任务，限制输入 32 MiB / 2400 万像素。异常格式、缓存不可写、生成结果不更小等情况回退原图。JPEG 保留 EXIF 朝向及 ICC 信息；CMYK JPEG 和特殊 PNG 不转换。
- 导航命中区域在同一帧内复用测量；点击/按下重新读取，保留真实控件优先级及拖动防误触逻辑。
- 阅读计数按元素初始化去重，并合并同路径的并发请求；存储被禁用不会打断初始化，失败允许后续重试。
- Markdown 源请求对响应头和响应体都有 2.5 秒截止时间，超时使用文档中自带的源内容；保留缓存验证，避免无限等待。重试脚本沿用版本 URL。
- 阅读浮动按钮的滚动处理按帧合并；离开阅读页后清理 body 中的按钮及延迟初始化。981–1200px 宽度下缩短目录树分支间距，给六级标题保留可读宽度。
- 站内切页按目标文档恢复完整 CSS 顺序，更新变化的资源版本；顺序未变的共享样式不重新插入，避免直开与切页出现不同层叠结果。
- 音乐播放器销毁时移除全局监听、释放媒体源，并阻止已销毁实例继续异步播放。清理临时解析文档中的音视频副本，释放浏览器原生 RemotePlayback 保留的旧文档；不禁用实际播放器的远程播放能力。
- 隐藏留言板的入场位移增加 24px 上限，消除桌面首页的横向溢出；打开后的尺寸、位置和视觉保持不变。

## 已取得的测量证据

测试环境：本机 Edge / Chromium，桌面 1440px 与移动视口 390px。设备模拟不等同于真机测试。首次服务端生成成本与缓存命中后的图片传输分开测量。

### 相同图片集合对照

使用相同构建 HTML、相同图片源，只替换预览响应；强制加载同一组目标图片，消除原图/预览解码速度不同导致的懒加载数量差异。单位为实际图片字节，不是整页首屏时间。

| 页面/集合 | 原图字节 | 预览字节 | 下降 |
| --- | ---: | ---: | ---: |
| 回忆页，15 张图片 | 54,887,077 | 2,122,768 | 96% |
| 朋友页，本轮加载的 16 个图片请求 | 9,711,011 | 5,775,082 | 41% |
| 工具页，12 个本地图片请求（包含背景） | 15,771,717 | 2,476,419 | 84% |
| C 语言文章封面，现有 WebP | 49,092 | 49,092 | 不转换 |

上述对照验证图片容器几何尺寸不变、无破图，以及回忆弹窗继续加载原图。输出：`local-only/media-preview/report.json` 与同目录的前后截图。初次生成本次回忆 JPEG 预览最慢约 547ms/张（本机），之后命中磁盘缓存；不能将暖缓存结果表述为冷启动延迟。

### 固定事件数对照

在 4 倍 CPU 节流下，同一批 240 次指针事件，桌面导航相关 `getBoundingClientRect` 调用由 2160 次减少为 6 次。文章页重复初始化四次的额外阅读计数请求由 1 次减少为 0 次。这是确定性工作量对照，不是 FPS 或打开速度的倍数承诺。

`tests/performance-audit.browser.cjs` 的 `loadMs` 是包含观察等待期的整段采样时长，不能当作网页加载时长；`decodedKB` 是资源响应体字节数，不是解码后的位图内存。原始报告在 `local-only/performance-audit/`。

### 连续切页与交互

每轮依次访问文章、工具、回忆、首页、朋友页，在同一文档内运行三轮，等待异步任务并强制 GC 后记录浏览器 DOM 计数：

| 视口 | 第 1 / 2 / 3 轮文档数 | 第 1 / 2 / 3 轮节点数 | 第 1 / 2 / 3 轮监听数 |
| --- | --- | --- | --- |
| 1440px | 1 / 1 / 1 | 1289 / 1696 / 1696 | 298 / 312 / 312 |
| 390px | 1 / 1 / 1 | 1262 / 1669 / 1669 | 298 / 312 / 312 |

修复前桌面文档数为 2 / 3 / 4，节点数为 1921 / 3442 / 4556，监听数为 304 / 368 / 418。内存快照定位了音乐播放器全局监听和临时音频副本的原生引用；修复后后两轮不再线性增长。此测试验证特定路线的生命周期，不代表整个应用不存在任何内存增长。

朋友页另以 GPU 合成开启的浏览器录制拖动、松手、缩放，覆盖桌面/手机与深浅主题，每组采样 199–206 帧，并比较参考样式几何与像素。几何一致，平均像素差 0.106–0.312/255；动态星空等造成的小幅像素差不能解读为完全逐像素相同。真实触摸屏及其他浏览器仍需真机确认。

## 复现

常规检查：

```sh
go test -race ./...
go vet ./...
node --test tests/*.test.cjs
```

在具备 Playwright 和 Edge 的环境里，指向本地站点运行现有浏览器套件。测试实际源码时需要源码资源覆盖，HTML 模板则必须重新构建后验证，不能只覆盖 JS/CSS。`local-only/run-browser-checks.cjs` 是本工作区的临时运行器，不属于可提交的公共测试依赖。

生成只读图片审计及浏览器用预览文件：

```sh
preview_audit_dir=$(mktemp -d /tmp/blog-preview-audit.XXXXXX)
BLOG_PREVIEW_AUDIT="$preview_audit_dir" go test ./cmd/server -run TestMediaPreviewAssetAudit -v -count=1
BLOG_PREVIEW_AUDIT="$preview_audit_dir" BLOG_PREVIEW_BUILD=/path/to/fresh/public node tests/media-preview.browser.cjs
```

`media-preview.browser.cjs` 的直接运行依赖本地站点提供其余运行时资源，图片读取仅限公开种子及公开媒体文件。`page-lifecycle.browser.cjs` 检查反复无刷新切页后的节点、监听器及浮动 UI；必须同时验证直开和站内切换。

## 最终验证与边界

本轮使用最新模板构建的隔离 Hugo 输出（178 页、228 个静态文件）验证 HTML，并覆盖当前源码资源及生成的预览图；运行器检查构建和图片审计文件存在，防止失效路径悄悄退回旧页面。未重新部署现有站点，未覆盖用户内容数据。

通过的检查：

- Go 全套竞态测试与 `go vet`；预览回退、元数据、缓存失效、范围请求、取消及清理边界。
- Node 六个单元测试文件：文档过渡、代理配置、Markdown 超时回退、样式顺序、阅读滚动合帧、阅读计数去重。
- 浏览器：性能工作量断言、图片对照、三轮页面生命周期、音乐选曲/播放/暂停/再次初始化、阅读目录布局、文章控件优先级、导航意图与入口、朋友页运动与 GPU 合成、同日回忆堆叠、慢/失败资源就绪、手机手势、深浅主题与视觉回归。
- 手机公开页面及工具共 17 条路线，在 360×640 与 844×390 检查布局、可点击控件与脚本错误。其他专项覆盖 390px、820px、900px、1024px、1440px 和 1920px 等视口；模拟触摸、鼠标及减少动画模式。

未覆盖：真机 Safari / Android、中低端设备和真实移动弱网。大背景图、外部图片和不转换格式仍可能产生明显带宽开销；不宣称所有设备绝无卡顿，也不把本机采样作为生产环境 Core Web Vitals 达标证明。上线后应结合真实用户的 LCP、INP、CLS 和错误率继续观察。

当前不部署、不自动提交；生成缓存是运行时可再生数据，不需要提交到 Git。
